## Default markup

Add `data-bs-toggle="tooltip"` and a `title` to the element. `data-bs-placement` puts the tooltip at the top, bottom, left or right.

<Example>
<div class="btn-list">
  <button type="button" class="btn" data-bs-toggle="tooltip" data-bs-placement="top" title="Tooltip on top">Tooltip on top</button>
  <button type="button" class="btn" data-bs-toggle="tooltip" data-bs-placement="right" title="Tooltip on right">Tooltip on right</button>
  <button type="button" class="btn" data-bs-toggle="tooltip" data-bs-placement="bottom" title="Tooltip on bottom">Tooltip on bottom</button>
  <button type="button" class="btn" data-bs-toggle="tooltip" data-bs-placement="left" title="Tooltip on left">Tooltip on left</button>
</div>
</Example>

## Tooltip with HTML

Set `data-bs-html="true"` to allow HTML in the title, for example to emphasize one word.

<Example>
<button type="button" class="btn" data-bs-toggle="tooltip" data-bs-html="true" title="<em>Tooltip</em> <u>with</u> <b>HTML</b>">Tooltip with HTML</button>
</Example>

To use your own options, create the instance yourself. It replaces the one Tabler created, so only your options apply:

```js
const el = document.getElementById('my-tooltip');
new tabler.Tooltip(el, { customClass: 'tooltip-wide', delay: 300 });
```

To read or control the existing instance without changing its options, use `tabler.Tooltip.getInstance(el)` or `tabler.Tooltip.getOrCreateInstance(el)`.

### Promise return values

`show()`, `hide()` and `toggle()` return a Promise that resolves after the transition ends, right after `shown.bs.tooltip` or `hidden.bs.tooltip` fires. Use it to run code after the tooltip has finished opening or closing:

```js
const tooltip = tabler.Tooltip.getOrCreateInstance(el);
await tooltip.show();
console.log('Tooltip is visible');
```

The Promise never rejects. It also resolves, without doing anything, when the call has no effect: the tooltip is already shown or hidden, it has no content, it is disabled, or a listener called `preventDefault()` on `show.bs.tooltip` or `hide.bs.tooltip`. `toggle()` waits for the `delay` option first. If another call replaces it during that wait - the pointer leaves, focus moves, or `toggle()` runs again - the earlier Promise resolves without the tooltip being shown or hidden, so `await tooltip.toggle()` does not guarantee that the tooltip is visible. To act only when the tooltip really changed state, listen for `shown.bs.tooltip` or `hidden.bs.tooltip` instead.

## Accessibility

- A tooltip only describes; it never replaces a name. The trigger still needs its own text or `aria-label`.
- The trigger must be focusable. Bootstrap shows the tooltip on focus as well as on hover, so a `span` or an `a` without `href` leaves keyboard users with nothing.
- Never put a link, a button or a form field inside a tooltip. It disappears on blur, so nothing in it can be reached. Use a popover for that.
- Tabler enables HTML in a tooltip only when you set `data-bs-html="true"`. Leave it off for text that comes from users.
- Do not attach a tooltip to a disabled control - a disabled element fires no events. Wrap it in a focusable span instead.
