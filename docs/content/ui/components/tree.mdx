## Overview

A tree shows nested items, such as folders and files. Folders are native `<details>` elements, so they open and close without JavaScript. You can add links, icons and checkboxes. Checkboxes need a small script, which starts on its own.

## Basic example

Build a tree from nested lists. A folder is a `<details>` element with a `<summary class="tree-node">` and a `<ul class="tree-children">`, so it opens and closes without JavaScript. Add `open` to expand a folder. A leaf is a `<span class="tree-node">`.

<Example>
<ul class="tree">
  <li>
    <details open>
      <summary class="tree-node">Documents</summary>
      <ul class="tree-children">
        <li>
          <details>
            <summary class="tree-node">Invoices</summary>
            <ul class="tree-children">
              <li><span class="tree-node">january.pdf</span></li>
              <li><span class="tree-node">february.pdf</span></li>
            </ul>
          </details>
        </li>
        <li><span class="tree-node">notes.txt</span></li>
      </ul>
    </details>
  </li>
  <li><span class="tree-node">readme.md</span></li>
</ul>
</Example>

## Icons

Put an icon with `.tree-icon` before the label of any row. Use a different icon for folders, files or an open folder.

The examples use [Tabler Icons](https://tabler.io/icons) as inline SVG with `stroke="currentColor"`, so the icon follows the text color in light and dark mode. Any other icon works too, as long as it is an element with the `.tree-icon` class.

## Links

Use `<a class="tree-node">` for a row that goes somewhere. Add `.active` and `aria-current="page"` to the current one.

<Example>
<ul class="tree">
  <li>
    <details open>
      <summary class="tree-node">Getting started</summary>
      <ul class="tree-children">
        <li><a class="tree-node" href="#">Installation</a></li>
        <li><a class="tree-node active" href="#" aria-current="page">Quick start</a></li>
      </ul>
    </details>
  </li>
  <li><a class="tree-node" href="#">Changelog</a></li>
</ul>
</Example>

## Checkboxes

Add `data-bs-toggle="tree"` to the root list and put a `.form-check-input` in each row. Checking a folder checks everything inside it, and a folder with only some children checked becomes indeterminate. The initial state is read from the checked leaves, so mark only the leaves as `checked`.

A leaf row is a `<label>` so its text toggles the checkbox. In a folder the checkbox needs its own `aria-label`, because a click on the folder text opens or closes the folder.

<Example>
<ul class="tree" data-bs-toggle="tree">
  <li>
    <details open>
      <summary class="tree-node">
        <input class="form-check-input" type="checkbox" aria-label="Projects" />
        Projects
      </summary>
      <ul class="tree-children">
        <li><label class="tree-node"><input class="form-check-input" type="checkbox" checked /> Read</label></li>
        <li><label class="tree-node"><input class="form-check-input" type="checkbox" checked /> Write</label></li>
        <li><label class="tree-node"><input class="form-check-input" type="checkbox" /> Delete</label></li>
      </ul>
    </details>
  </li>
</ul>
</Example>

## Checkboxes on items only

Leave the checkbox out of the folder rows to let users select single items only. The folders then only open and close.

<Example>
<ul class="tree" data-bs-toggle="tree">
  <li>
    <details open>
      <summary class="tree-node">Design</summary>
      <ul class="tree-children">
        <li><label class="tree-node"><input class="form-check-input" type="checkbox" checked /> Figma files</label></li>
        <li><label class="tree-node"><input class="form-check-input" type="checkbox" /> Brand assets</label></li>
      </ul>
    </details>
  </li>
</ul>
</Example>

## Always expanded

Leave out `<details>` entirely to keep every folder open with no collapse toggle. A folder row is a `<span class="tree-node">`, or a `<label class="tree-node">` when it has a checkbox, followed by its `<ul class="tree-children">` — both are always rendered. Add `.tree-expanded` to the root list so every row starts where the collapse toggle would otherwise sit, since there is nothing left to toggle.

<Example>
<ul class="tree tree-expanded" data-bs-toggle="tree">
  <li>
    <label class="tree-node">
      <input class="form-check-input" type="checkbox" />
      Projects
    </label>
    <ul class="tree-children">
      <li><label class="tree-node"><input class="form-check-input" type="checkbox" checked /> Read</label></li>
      <li><label class="tree-node"><input class="form-check-input" type="checkbox" checked /> Write</label></li>
      <li><label class="tree-node"><input class="form-check-input" type="checkbox" /> Delete</label></li>
    </ul>
  </li>
  <li><label class="tree-node"><input class="form-check-input" type="checkbox" /> Audit log</label></li>
</ul>
</Example>

## Usage

The tree starts on its own for every `[data-bs-toggle="tree"]` element:

<CodeDocs name="tree-init" file="core/js/src/tree.ts" />

To create it from code, call `Tree.getOrCreateInstance(element)`. The `checked` getter returns the checked inputs, and each change fires the native `change` event on the input.

Once the cascade to parents and children settles, the tree fires `changed.bs.tree` on the root list, so code listening for the outcome does not need to read `checked` after every native `change`:

```js
document.querySelector('.tree').addEventListener('changed.bs.tree', (event) => {
  console.log(event.relatedTarget, event.checked);
});
```

## Accessibility

- The tree is made of plain nested lists and `<details>`, so screen readers announce the nesting and the expanded state without extra roles.
- Give every checkbox a name: a wrapping `<label>` for a leaf, an `aria-label` for a folder.
- Mark the current link with `aria-current="page"`, not only with `.active`.
